# ADR-001：采用 WebRTC DataChannel + 自建信令

- 状态：已接受
- 日期：2026-11-12
- 决策人：汪星同、张米奇
- 关联 Issue：#3、#11

## 背景

系统需要一对一私密聊天，核心诉求是“服务端不接触消息内容”。可选方案包括：传统 WebSocket 服务端转发、第三方 IM SDK、WebRTC DataChannel。课程周期短，团队 4 人，需要低运维、可演示。

## 决策

采用 WebRTC DataChannel 实现浏览器之间的点对点加密传输，自建一个轻量 WebSocket 信令服务，只负责房间管理与 SDP/ICE 转发；直连失败时使用 TURN 中继。

## 备选方案

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| WebSocket 服务端转发 | 实现简单、稳定 | 服务端可见消息，不满足隐私目标 | 不采用 |
| 第三方 IM SDK | 功能全、接入快 | 依赖外部服务、不可控、难体现工程能力 | 不采用 |
| WebRTC DataChannel | 加密直传、低延迟、浏览器原生 | NAT 穿透复杂、需要 TURN | **采用** |

## 后果

- 正面：私聊消息不落库；技术亮点明确；可演示“抓包看不到明文”。
- 负面：需要维护 STUN/TURN；部分校园网可能只能走中继；调试成本高。
- 后续：第 1 周完成双端 Spike；准备公共 STUN 与自建 coturn 两套配置；界面显示“直连/中继”状态。
