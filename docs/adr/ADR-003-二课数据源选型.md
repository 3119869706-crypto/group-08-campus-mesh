# ADR-003：二课活动数据源选型（RSS 优先）

- 状态：已接受
- 日期：2026-11-18
- 决策人：陈永学
- 关联 Issue：#16

## 背景

FR-15 要求系统每日 06:00 自动抓取校园二课公开活动，单次 60 秒内完成，按来源 URL 与标题哈希去重，失败时保留上次数据。抓取方式的选择直接决定 #16 的实现路径、稳定性和合规风险，因此在写业务代码前先做选型。

目标站点为江西师范大学通知聚合站 `https://jxnu-publish.asia/`（301 至 `https://publish.betterjxnu.cn/`）。

## 前置调研（2026-11-18 实测）

| 方案 | 结论 | 实测证据 |
|---|---|---|
| 直接解析 HTML | 不可行 | 首页 HTML 仅 5,643 B，可见文本 16 字（"JXNU PUBLISH 载入中"），`#root` 容器为空——React SPA，正文由前端注入 |
| 调用 `/api/notices` | 不可依赖 | 301 至 `publish.betterjxnu.cn` 后返回 503 `upstream connect error or disconnect/reset before headers` |
| 读取 `/rss.xml` | **可行** | 120 条结构化条目，字段含 title/link/guid/pubDate/description/category[]/enclosure，单次抓取 6.35 s |
| Playwright 渲染后解析 | 可行但成本高 | 需 headless Chromium，CI 体积与耗时增加，渲染后仍需解析 DOM，收益低于 RSS |

站点 `robots.txt` 为 `User-agent: * / Allow: /`，且 `Sitemap: https://jxnu-publish.asia/rss.xml`——站点以 Sitemap 指向 RSS，等同明示批量取数的推荐入口。

## 决策

1. **以 `/rss.xml` 作为二课活动的唯一主数据源**，不抓 HTML、不调用 `/api/notices`。
2. 生产实现用 TypeScript，解析库为 `fast-xml-parser`；Python 脚本仅作 Spike 验证，放 `docs/spikes/`，不进 `apps/`。
3. 每日 06:00 定时抓取（`node-cron`，时区 Asia/Shanghai），总预算 60 s，超时中止并保留旧数据。
4. **双层去重**：`source_url` 唯一约束（同页重复入库）+ `content_hash = SHA256(归一化标题 + 开始时间)`（同活动换链接重发）。
5. 抓取失败**不删数据**：接口返回 `stale: true` 与 `lastFetchedAt`，前端标注数据时间（对应 SRS 4.3 降级能力）。
6. 若 RSS 不可用或页面结构变化导致解析失败，**降级为半自动 JSON 导入**（`POST /activities/import`），爬虫优先级降为 P2。
7. 合规：可识别的 UA（`CampusMeshBot/0.1`，带联系方式）、单域限速 ≥1.5 s、只抓公开页面。

## 备选方案对比

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| HTML + cheerio | 不依赖站点提供订阅源 | SPA 空壳，需浏览器渲染；页面改版即挂 | 不采用 |
| `/api/notices` 接口 | 字段最全、可分页 | 当前 503 不可用，无 SLA，随时可能变 | 不采用 |
| **RSS** | 稳定、结构化、合规明示、1 请求取全量 | 仅最近 120 条；时间/地点/绩点需启发式抽取 | **采用** |
| Playwright 渲染 | 能拿任意页面 | CI 体积与耗时大，脆弱（选择器依赖 DOM） | 仅作兜底，不纳入 #16 |

## 后果

- **正面**：抓取器只需 1 个请求、6 s 级完成，60 s 预算宽松；字段结构稳定，去重与入库逻辑简单；合规风险低，答辩可引用 robots.txt 与 Sitemap 佐证。
- **负面**：
  - RSS 只覆盖最近 120 条，历史活动不在其中——必须靠数据库累积，不能每次现取。
  - 时间/地点/绩点只能从中文描述启发式抽取，实测覆盖率：开始时间 52/120（43%）、地点 20/120（17%）、绩点 2/120（2%）。
  - 依赖站点持续提供 RSS；若下线需走降级方案。
- **已知误判**：把"10月25日12:00 截止"当成活动开始时间。已在 Spike 中按截止语义（`截止/截至/前/补充/更新`）过滤，抽不到则留空，**宁可空不可错**。
- **后续需要做的事**：
  1. #16 中实现 TS 抓取器，解析器选择器配置化（`parser.config.json`），页面改版只改配置。
  2. 用 `tests/fixtures/rss_sample.xml`（12 条裁剪快照，已移除他人群二维码）做解析回归。
  3. 优先从标题括号信息（如"（10月27日 W7203）"）取高置信度字段，描述兜底；低置信度条目进人工复核队列。
  4. 数据库侧按 `Activity` 表累积历史，接口按 `start_time` 排序提供检索。
