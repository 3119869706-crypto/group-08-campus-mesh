# 测试计划

## 1. 目标

- 核心模块（Service / API 层）测试覆盖率 ≥40%。
- CI 在 PR 与 push 时自动执行 lint、typecheck、test、build。
- 测试断言必须校验真实行为，禁止 `expect(true).toBe(true)`。

## 2. 分层策略

| 层级 | 范围 | 工具 | 负责人 |
|---|---|---|---|
| 单元测试 | 工具函数、Service、Prompt 组装 | Vitest | 各模块作者 |
| 接口测试 | REST API、鉴权、错误码 | Vitest + supertest | 陈永学 |
| E2E | 发帖、私聊、总结主流程 | Playwright（可选） | 陈永学 |
| 手工测试 | 双端联调、弱网、移动端 | 清单 | 全组 |

## 3. 核心用例清单

### 匿名身份
- [ ] 首次访问生成 ID；刷新后不变
- [ ] 令牌过期返回 401
- [ ] 本地存储被清除后重新生成

### 校园墙
- [ ] 发帖成功并出现在列表
- [ ] 含 `<script>` 的内容被转义
- [ ] 重复点赞不重复计数
- [ ] 3 次举报后自动隐藏

### P2P 私聊
- [ ] 双端建连并互发消息
- [ ] 错误口令无法加入
- [ ] 断网 10 秒内重连并补发
- [ ] 服务端日志无消息明文

### AI 与总结
- [ ] 未配置 Key 时返回 503 并降级
- [ ] SSE 流式输出可中断
- [ ] 800 字总结 30 秒内完成
- [ ] 导出 Markdown 与预览一致

## 4. 覆盖率与报告

```bash
pnpm test:cov
```

报告输出到 `coverage/`，CI 中上传为 artifact；低于 40% 时在 PR 中说明原因。

## 5. 缺陷管理

- 缺陷统一建 `[Bug]` Issue，附复现步骤、环境、截图。
- 修复 PR 关联 Issue，写 `Closes #`。
- 严重缺陷（无法启动、数据丢失、密钥泄露）立即停止合并，优先修复。
